# MedAxis Global Pharma frontend — Release 1, Steps 1–7

Next.js 15.5 App Router, strict TypeScript, Tailwind CSS 4, next-intl, and the Express `/v1` REST API. The Next.js 15 template's TypeScript settings are retained, with `allowJs: false` and explicit `noImplicitAny: true`. Next 15 retains the requested Edge `middleware.ts` convention. No database or R2 SDK is used by this application.

## Run locally

Use Node.js 22.13+ and npm. From `frontend/`:

```sh
npm ci
cp .env.example .env.local
npm run dev
```

On Windows PowerShell, use `npm.cmd` if execution policy blocks `npm.ps1`, and `Copy-Item .env.example .env.local`. Set `NEXT_PUBLIC_API_BASE_URL` to the Express **origin**, such as `http://localhost:4000`, without `/v1`; all client paths include the version. There is no hardcoded API fallback. Express must allow the frontend origin in its credentialed CORS configuration. Server-side admin callers must explicitly forward their incoming session cookie; `credentials: 'include'` alone does not forward browser cookies during server rendering.

`API_INTERNAL_BASE_URL` optionally overrides the origin only on the server. `NEXT_PUBLIC_SITE_URL` sets absolute canonical/sitemap URLs. `NEXT_PUBLIC_R2_PUBLIC_BASE_URL` allows an additional public HTTPS asset origin in both Next Image and CSP. Configure public variables before building; they are embedded in the browser bundle. Keep `REVALIDATE_WEBHOOK_SECRET` private and identical to Express.

## Verify

```sh
npm run typecheck
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

Playwright starts isolated Next.js and mock Express servers on ports 3100 and 4100; it needs no database, account, or staging backend. Tests and their configurations are included in typechecking. `npm run lint` is also available.

An installed Chrome/Edge can be used by setting `PLAYWRIGHT_CHANNEL=chrome` or `msedge` instead of downloading Chromium.
After a production build, set `E2E_PRODUCTION=1` to run the same suite against `next start`.
That build must use the fixture origins/public variables in `playwright.config.ts` (including API `http://127.0.0.1:4100` and the browser fixture site key). Run `tests/e2e/mock-api.ts` while building catalog pages, then stop that helper before Playwright starts its own server. This fixture build is for local tests only; production requires the real API/site key.

## Foundation contracts

- Only `/` consults `medaxis_locale`, then `CF-IPCountry`/`Accept-Language`. Its 307 response is private and uncached. Direct locale paths retain their locale. Redirects use the original request URL with `skipMiddlewareUrlNormalize` enabled, preserving the hostname (including `127.0.0.1`) so preference cookies stay on the same origin. The next-intl configuration disables automatic locale detection and alternate Link headers; page metadata owns canonical/hreflang tags.
- `/q`, `/admin`, `/api`, framework paths, and static files bypass locale routing. Admin pages additionally use their own backend-validated session boundary. Independent quotation/admin roots and private headers prevent public provider, indexing and referrer leakage.
- Historical catalog URLs are looked up through existing Express detail endpoints with manual redirect handling. A module-local LRU stores up to 500 redirect/404 results for one hour. Live canonical paths and transient failures remain uncached, so new slug edits can take effect immediately. Invalid, external, private, cross-kind, and self-loop targets are rejected. The cache is per Edge isolate and resets on cold starts; existing cached redirects may remain until their TTL expires.
- `apiRequest(path, schema, options)` requires a runtime schema (for example a Zod DTO schema) and returns a validated `ApiSuccess<T>`. Errors are `ApiError` with `status`, `code`, `details`, `requestId` and optional `retryAfterSeconds`. Proxy HTML is never exposed. GET and documented keyed POST operations (RFQ quick/cart and quotation acceptance) receive at most three retries after the first attempt for 429, 500, 503, or network failures. This includes 500 as required by API-Spec §1.6. Integer `Retry-After` takes precedence; fallback exponential jitter is capped at 30 seconds. Other 4xx responses and unsupported/unkeyed writes are not retried. Request body and key are captured once. Upload, PDF and admin binary/SSE transports remain separate from JSON validation; uploads/auth mutations are never automatically retried.
- `/sitemap.xml` is the combined sitemap specified by Step 1. It consumes only the published Express feed, includes all four entity kinds, and emits reciprocal links plus entity-specific English `x-default`. Missing Chinese translations (`zhCN: null`) are omitted rather than inventing noncanonical URLs. A backend failure yields uncached 503. Only implemented static pages are added. Feed fetches and route output revalidate hourly and on catalog webhooks.
- `POST /api/revalidate` accepts `{ "tags": ["catalog", "cms", "settings"], "request_id": "optional UUID" }`, matching the existing backend. An optional `paths` array accepts public localized paths and `/sitemap.xml`. Authentication is checked before parsing; unknown tags, private targets, and malformed payloads are rejected. Catalog tags also invalidate the sitemap route. Later catalog/CMS/settings fetches should use the corresponding tags.
- Security headers allow self-hosted assets, the configured API, Cloudflare Turnstile and configured Plausible origins. Static CSP allows inline bootstrap scripts required by App Router/ISR, without production `unsafe-eval`; adopting per-request nonces would require dynamic rendering. Typography uses the local system/CJK font stack; no remote fonts are loaded.

The current backend has no featured selector: the first published catalog page supplies the preview, manufacturer/category names and generic ingredients. Catalog and CMS requests use their existing revalidation tags. Backend outages show a localized fallback while the shell and custom requirement entry remain usable.
- Header navigation links to the implemented product listing, manufacturer/ingredient directories and services. Quick Quote and the RFQ list share the Step 4 submission form; the separate **Add to RFQ list** action still only saves medicine requirements locally. The owner's WeChat QR is included at `public/images/wechat-contact.jpeg` and displayed in both languages, with WeChat first in Chinese. The tracker explicitly projects same-origin public pageviews to event name, clean URL and configured domain. Custom events, event properties, referrers, unknown metadata, private paths and query/hash data are dropped. No cart contents or form values are passed to analytics. Tests intercept the configured fixture domain rather than sending live analytics.
- Footer utility pages (`privacy` and `terms`) are `noindex, nofollow`, linked with `nofollow`, and excluded from the sitemap. Modals use native dialog focus containment, Escape/backdrop closing and focus restoration. The mobile navigation and homepage are checked at 320px as well as desktop widths.

Example typed request:

```ts
import { z } from 'zod';
import { apiRequest } from './lib/api-client';

const dto = z.object({ products: z.array(z.object({ id: z.string(), slug: z.string() })) });
const { data } = await apiRequest('/v1/public/products?locale=en', dto, {
  next: { revalidate: 3600, tags: ['catalog'] },
});
```

## Searchable public catalog — Step 3

- `/[locale]/products` consumes only the documented list query keys and actual `data.facets` / `meta.pagination`. Filters omit blanks and reset pagination on application. Search and filter forms remain native GET forms without JavaScript; enhanced navigation shows a pending message while Next.js resolves the latest route. Search/filter permutations are `noindex, follow` with clean canonical URLs. Anonymous filtered reads use `no-store`; default catalog/profile reads retain `catalog` ISR tags.
- Public Zod schemas allowlist product identity, translated content, packaging/specifications, images and master profiles. They validate locale/translation/alternate-slug consistency and strip unknown fields from every nested object, including metadata and facets. Public DTOs require `id`; no admin `_id` or database model is imported. Rich HTML is reduced to plain text at the adapter boundary and rendered through React. Structured data is explicitly projected and escapes script delimiters; it contains no offers, prices, ratings or invented review/certification fields.
- Product detail pages prebuild at most 12 published sitemap entries per locale; dynamic slugs remain enabled with hourly/tag invalidation. Encoded Unicode route parameters are decoded once and validated before use. Shared `components/catalog/ProductCard` serves home, listing and hubs; the Step 2A home import path is retained as a re-export. Real image URLs are allowlisted, have fixed dimensions/frames and use a stable error fallback.
- Master directories use the cached published sitemap feed, resolve at most 12 profiles per page, and run at most four profile requests concurrently. Complete select pickers are offered only when the entire kind has at most 12 entries and every profile resolves. Larger/incomplete feeds use localized-slug inputs plus paginated directory links. The homepage category select uses that same completeness rule. No collection-list API or one-page-as-directory shortcut is invented.
- Metadata uses the exact `alternate_slugs`. English-only entities omit Chinese hreflang. A direct Chinese fallback URL keeps its own canonical, English entity `x-default` and `noindex, follow`. The locale switcher maps known filter slugs across languages, resets pagination and clears unresolved slug filters while preserving other query context. Page metadata resolves before headers via `htmlLimitedBots`, and search loading uses a client pending state so missing product URLs retain HTTP 404.
- Middleware retains actual HTTP 301 for historical product/master slugs. Detail readers opt into validated manual redirects and surface `ApiRedirect`; generic requests still reject redirects. Invalid external/private/cross-kind targets are rejected without a retry loop. If a redirect changes after middleware has run, the server renders a safe moved-entry link rather than issuing a falsely described 308. Response body cancellation never waits for an unfinished tee branch, preserving bounded retries and sanitized proxy errors.
- `/services` and `/services/pharmaceutical-sourcing` use the supplied sourcing/documentation/handling capabilities. The combined sitemap now adds the implemented indexable listing, directories and services; utility pages, fallback translations, private paths and search/filter permutations remain excluded. Existing webhook authentication/tags are retained.
- Empty results prefill Quick Quote with a custom medicine name, without a product ID. Catalog/custom rows, merge behavior and stored cart version remain shared across all views.

## RFQ submission — Step 4

- `components/rfq/RfqDialog.tsx` handles both one-line Quick Quote and the 1–100-line cart flow. `CartDrawer` moved out of the shell; existing shell actions and cart storage remain shared. Nested contact/line schemas in `lib/rfq.ts` enforce B2B company, a contact channel, Chinese/China email, ISO country codes, positive safe-integer quantities and catalog versus uncatalogued lines. Custom units receive server validation without reading private settings. Optional line notes, delivery details and quotation currency are memory-only.
- `hooks/useRfqSubmission.ts` wraps a memory-only submission state machine. It synchronously locks duplicate submits, generates a UUID v4, freezes the business snapshot and sends identical body/header keys. The existing API client captures serialized JSON once per retry sequence, applies per-attempt deadlines and honors Retry-After. Uncertain responses and 409 keep the intent locked for same-endpoint replay; there is no invented RFQ status endpoint. A 403 permits only challenge refresh with the same business snapshot/key. Validated 400/422 rejections permit correction, while later errors cannot erase an already uncertain outcome. Replays stop at the backend's 24-hour key TTL and require contact with the team. Keep an unresolved page open: the key/contact snapshot is deliberately not persisted across reloads.
- A validated 200/201 shows `rfq_number`, without promising an SLA or treating delayed notification delivery as submission failure. Confirmed cart submissions remove submitted quantities and retain later additions. Quick Quote does not discard an unrelated cart. Closing a resolved form clears its contact/file state; a subsequent submission gets a fresh key.
- Set `NEXT_PUBLIC_TURNSTILE_SITE_KEY` before building. Without a key, submission/upload stay disabled and official contact channels remain available. Cloudflare's script/frame/connect origins already belong to the CSP. Browser code sends only the public key and challenge token; server secrets and verification remain in Express. Challenge tokens are refreshed after use, and automatic RFQ retries still replay the captured full body.
- `PrescriptionUpload` uses one-shot, credentialed XHR multipart requests for progress and cancellation. JPEG/PNG/PDF signature/type/size checks run before upload; Express remains responsible for authoritative validation/encryption. FormData owns its boundary. At most five validated prescription IDs and blob previews remain in memory; URLs are revoked on removal/unmount. Upload errors are sanitized and never automatically retried. No public CDN or browser persistence holds prescription files. The form explains the backend's 90-days-from-upload / 14-days-after-terminal-state retention limit, whichever is earlier, and remains usable without attachments.
- Only upload and RFQ requests containing prescription IDs include the HttpOnly staging-session cookie; other public JSON reads/writes still omit credentials. Frontend/API must be compatible same-site HTTPS origins with credentialed CORS. Locally use the same hostname on both sides (`localhost` on both, or `127.0.0.1` on both). Do not weaken SameSite=Strict or copy the cookie into browser storage.
- English/Chinese field validation, request IDs and recovery actions preserve inputs. Official contact channels use the original WeChat JPEG, Chinese-first order and configured WhatsApp. Chinese guidance explains email quotation links and direct conversation, without claiming automated WeChat notifications. No RFQ inputs, files or cart contents are sent to analytics.

Response loss/500 triggers a read to recover already-accepted state, or an actionable same-acceptance retry. The backend currently enforces atomicity by token/version, not by this header key. - Expired/superseded/missing states display safe guidance and discard inaccessible commercial data. Only an expired current link offers request-refresh. Definite validation errors retain editable inputs; uncertain decisions retain inputs and prevent another client POST while read-only status/contact recovery remains available. Expired refresh forms keep their notes even after transport failure. GET has no revision/refresh receipt fields, so it cannot confirm those requests.

Browser recovery tests use an interrupted HTTP body to isolate application retry behavior.

## Admin transport and RFQ/FX console — Step 6

- `/admin` has an independent dynamic/no-store root, without public locale routing, shell, cart or analytics. `/admin/login` stays outside the protected route group. Protected navigation requests a new document instead of reusing private Router Cache entries. Edge page responses verify the full session through Express and relay renewals; every sensitive server read independently checks `/v1/admin/auth/sessions` before forwarding the incoming full cookie. Server Components never write cookies. Read the raw Cookie header: Next's `cookies()` decodes percent escapes and changes Express's signed wire value.
- Browser logical `/v1/admin/*` requests use the fixed-origin Node `/api/admin/[...path]` adapter. Public requests retain their configured API origin and existing ownership rules. The BFF allowlists actual methods/paths/query keys, checks mutation Origin and frontend host, forwards only selected headers/cookies, rejects redirects and sanitizes JSON/proxy errors. Multipart bodies retain browser boundaries; binary/SSE bodies stream separately. No arbitrary URL target, local session signing or browser auth storage is introduced.
- Full `medaxis_admin_session` cookies map `/v1/admin` to frontend `/`; `pre_auth_session` maps `/v1/admin/auth` to `/api/admin/auth`. Signed values remain opaque and unchanged. Separate Set-Cookie values preserve HttpOnly, SameSite=Strict, production Secure, expiry and frontend host-only scope. The final clear wins over an earlier renewal for the same cookie. Configure `ADMIN_FRONTEND_ORIGIN` to the exact browser origin (defaults to `NEXT_PUBLIC_SITE_URL`) and include it in Express `PUBLIC_ORIGIN`. Use HTTPS in production and consistent local hosts; do not remove cookie protections to repair deployment configuration.
- Password login only opens the TOTP/backup-code form. MFA sends the same pre-auth cookie and only Express can issue a full session. Authentication writes never retry automatically; safe errors preserve field state and honor lockout Retry-After. Bootstrap uses the seeded enrolled authenticator. Authenticated enrollment is rotation, not a public bypass. The backend currently accepts password plus an unused backup code directly; PRD's additional email confirmation has no implemented endpoint and remains a registered discrepancy.
- RFQ search/status/buyer/date filters and pagination consume the actual array plus `meta.pagination`. FX cards preserve server decimal strings, mode, availability and staleness. There are no fabricated aggregate panels. The owner explicitly deferred accepted-payment, ready-to-dispatch, global-quotation and expiring-allocation summary metrics until their backend contracts exist. RFQ triage/quotation editing remain Step 7 work.
- `useAdminStream` owns one credentialed fetch stream with incremental, size-bounded event validation and in-memory deduplication. Backend comments arrive every 25 seconds; a 40-second watchdog detects missing traffic. A single 5–30-second jittered reconnect loop refetches RFQ/FX data after reconnection, without assuming durable replay. The BFF closes connections after 55 seconds under its 60-second route limit and aborts upstream work on disconnect. Deploy on a Node host/proxy that permits unbuffered streaming and this duration; verify deployed limits separately. Sound starts off and requires user interaction. Stream traffic never resets the client human-activity deadline or starts session polling. After 30 idle minutes the console locks, closes its stream and confirms logout; Express remains authoritative for inactivity/revocation on every operation.
- Sessions display actual masked device data and offer confirmed revocation of other sessions. Logout hides private children synchronously, waits for the backend response and reconciles uncertainty with a session read before a deliberate retry. Session loss triggers reauthentication. No passwords, codes, cookies, customer data or events are persisted in browser storage or sent to analytics/logging.
